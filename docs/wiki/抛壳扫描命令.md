# 抛壳扫描命令

[English](Shell-Ejection-Scan) | [命令参考](命令参考)

扫描器是**发现目标与生成候选规则的工具**，用于获取当前安装环境中的枪械、载具武器、座位和弹药规格。它不会自动证明每条生成规则都能工作，也不代表全部规则都应该启用。

---

## [1] 明确选择扫描模式

```text
/superbaddon shell_ejection scan
```

生成关闭状态的候选规则，推荐首次使用这一模式，但它仍会重写生成文件并重载外部规则。

```text
/superbaddon shell_ejection scan active
```

生成活动候选，并在命令执行过程中应用生成后的活动规则。active 不会扫描更大的注册范围，也不会提高识别精度；只有理解格式与副作用后，才应在可丢弃环境使用。

两者均要求权限等级 2。当前版本没有文档支持的按单个物品或命名空间筛选命令参数。

## [2] 扫描哪些内容

扫描器收集注册的枪械候选、载具类型，以及能通过临时载具实例检查获取的武器定义，再合并已经加载的载具所暴露的武器。它识别主模组 superbwarfare 和声明依赖它的附属命名空间，并在相关位置使用运行时／名称启发式判断。

临时实体用于检查，结束后会丢弃，不是有意向世界生成一整队载具。但构造函数及其他模组实体实现仍可能耗时或产生副作用，因此不应把扫描当成周期性维护任务反复执行。

座位检查上限为 32。未知弹药或不可访问的武器数据可能留下占位或不完整候选。已加载实例能补充纯注册检查没有的数据，但扫描未出现某把武器，也不能直接证明它无法手动配置。

## [3] 输出归属与删除边界

```text
config/superbaddon/shell_ejection/
├─ custom/                       # 长期维护规则，扫描器不会删除
└─ generated_scan/                # 每次扫描都会重建
   └─ <namespace>/
      ├─ items/<registry_path>.json
      └─ vehicles/<registry_path>.json
```

写入器在生成新文件前，删除完整的原 generated_scan/ 目录和旧单文件 generated_scan.json。custom/ 中的文件不会被该写入器删除，但仍会参与随后重载的规则集合。

> [!WARNING]
> 普通关闭模式扫描也可能把以前启用的生成文件换成关闭状态候选。两种模式执行前都应备份。以 .json 结尾、留在抛壳递归目录里的备份仍会作为活动输入读取，所以备份应移到目录外。

## [4] 检查候选字段

检查每个生成文件的 rules 数组，而不只是根对象中的说明元数据。逐项核对 enabled、priority、对象形式 target、允许弹药、抛壳条目和可能的击退字段。

根对象中的 owner 与 enabled_by_default 描述生成信息；嵌入的 content_control 不会被当前 format 5 解析器当成活动内容控制。内容限制必须写入[内容控制](内容控制)文件，而不是扫描元数据。

一个目标可能按已知弹药变体拆成多条规则。空弹药占位不能当成有效弹药定义。应对照实际载具检查注册 ID、座位下标和武器名；除非确实要修改装填行为，否则不要改动弹药消费者。

## [5] 从候选到正式规则

1. 备份配置，在加载了目标模组和数据包的测试世界执行普通非激活扫描。
2. 选取一个目标的有用候选，将其**移动**到 custom/ 中的维护文件。理解后再删除无关变体和说明内容。
3. 显式设置 rules[].enabled，明确分配优先级，只保留真正需要的功能。例如，只想改弹壳时，不应顺手替换允许弹药列表。
4. 执行 `/superbaddon shell_ejection reload_external`，检查日志，测试应该匹配和不应该匹配的枪械／座位／弹药组合。
5. 将已验证维护文件纳入版本管理。后续扫描只是可丢弃的发现结果，不再作为手工调参的唯一来源。

应移动而不是盲目复制活动重复项。重命名或重新扫描可能改变同优先级规则的 ID 排序，详见[抛壳配置](抛壳配置)。

## [6] 理解输出与失败

枪械、载具、文件和规则数量只表示发现与生成结果；临时实例数不是故意放进世界的实体数量，已加载载具数也不是完整整合包兼容覆盖证明。

写入失败时保留日志，检查服务端目录写入权限和存储状态。由于写新内容前先删除旧生成输出，中断可能留下不完整结果；应恢复备份，不要默认旧文件仍然完整。扫描成功却无效果时，先检查规则内开关和实际目标／弹药，而不是再次扫描。
