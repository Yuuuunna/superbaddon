# 数据格式版本与迁移

[English](Data-Format-Versions) | [配置总览](配置总览)

当前源码有多套互不等同的 JSON 格式。一个格式中的版本号或字段名，不能搬到另一个格式中当作通用兼容开关。

---

## [1] 格式对照

| 数据 | 版本／类型标识 | 正确位置 |
| --- | --- | --- |
| 抛壳、弹药覆写、击退 | 根数值 format: 5 和 rules 数组 | 外部抛壳目录，或数据包 data/<namespace>/shell_ejection/ |
| 内容控制 | 固定结构，没有必需格式编号 | config/superbaddon/content_control.json |
| 载具配方覆写 | 固定结构，groups／overrides | config/superbaddon/vehicle_recipe_override.json |
| 穿透 | 固定结构，兼容部分旧名称 | config/superbaddon/armor_penetration.json |
| MTS 设置 | 固定结构，另有客户端／会话职责 | config/superbaddon/mts_compat.json |
| 计数弹壳配方 | type 为 superbaddon:shell_reloading | 数据包 recipes 目录 |

数据包 pack.mcmeta 有自己的格式／版本体系，不由抛壳 format 5 决定。给普通合成配方加上 format 5，也不会让它变成抛壳规则。

## [2] 当前抛壳包装

完整的不抛壳规则：

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "ejection": { "default": { "mode": "none" } }
    }
  ]
}
```

解析器拒绝缺少或不等于 5 的格式号、根数组和缺失 rules 数组。提供 target 时必须为对象。仅将旧文件的数字改成 5，不会自动迁移其中的字段结构。

## [3] 校正旧假设

| 旧写法／假设 | 当前解释与迁移 |
| --- | --- |
| 字符串 target | 改成包含正确 guns／projectiles／vehicles／weapons 的对象 |
| 根 enabled_by_default 控制全部规则 | 它是元数据，应逐条显式设置 rules[].enabled |
| 在扫描输出内嵌 content_control | 将实际限制移动到独立 content_control.json |
| 外部目录天然覆盖数据包 | 明确指定优先级，并考虑规则 ID 排序 |
| 关闭一条规则就能全局停止抛壳 | 需要压制较低匹配时，应保留活动 mode-none 规则 |
| generated_scan.json 长期作为手工文件 | 执行扫描前将维护内容移到 custom/ |
| 外部重载撤销全部弹药内存修改 | 从原始数据完整重载／重启，并验证恢复 |

迁移时不要把枪械 ID 随意改成载具 ID，也不要猜测武器名。当前扫描输出只作为结构参考，不应无差别替换原来手工维护的行为。

## [4] 保留的兼容形式

抛壳解析器接受目标集合的单值或数组形式；没有提供优先 ports 数组时，兼容旧 points 数组。推荐模式为 drop／store／none，旧别名见[抛壳配置](抛壳配置)。未知模式可能回退为 drop，不能依赖未识别拼写来关闭行为。

弹药选项接受字符串或消费者对象，并兼容身份字段的部分大小写变体，但这不保证旧主模组消费者内部字段在升级依赖后仍有效。

穿透支持规范 snake_case 键，以及 armorPenetrationByWeapon、fullArmorBypassWeapons、如 `"namespace:id=35%"` 的旧数组形式和旧根级爆炸字段。优先使用[护甲穿透](护甲穿透)中的规范嵌套形式，不要同时提供两套名称：旧部分穿透表在规范表之后读取，全穿透集合则合并。

旧根级爆炸字段为 explosionMinArmorPenetration、explosionInnerRadiusFactor、explosionOuterFalloffPower，嵌套 explosion 字段优先。这些别名都不能代替独立文件，也不是附属统一格式版本。

## [5] 安全迁移步骤

将原配置归档到所有活动扫描目录之外，确认真实格式及源码／依赖版本。先把一个目标改写成完整当前格式，明确 ID 与意图，不要保留依赖旧元数据开关的假设。

校验 JSON，重载正确系统，分别验证应匹配和不应匹配的情况。涉及哪些功能，就检查哪些实际行为：弹药选择／扣除、抛壳位置、击退、配方输出和重启后的状态。通过后再迁移下一组。

抛壳维护文件放到 custom/，生成输出保持可丢弃。资源限制必须配合存档备份，删除设置不能还原已丢弃实体。配方数据需要重建配方表，不能只刷新内容查询缓存。

## [6] 文档地址兼容

旧 Wiki 地址 Configuration、Home‐ZH 和双扩展名侧栏继续保留为入口。恢复后的旧文原样归档，其中可能有不符合当前格式的示例。正式双语功能页才是当前格式参考。

文档校验器检查严格 JSON 语法、站内链接和已知页面覆盖，不替代模组解析器、主模组消费者反序列化或实际注册表测试。格式验证与游戏行为验证应明确区分。
