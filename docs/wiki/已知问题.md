## [1] 源码确认的行为缺口

| 范围 | 当前限制 | 安全处理 |
| --- | --- | --- |
| 普通物品／方块只禁配方 | 输出过滤检查 block_load 而非 recipes_only；载具装配有单独生效的模式检查 | 使用已验证的只删配方方式，不要直接升级为资源阻止 |
| 弹药覆写回退 | 修改内存定义但没有通用原始快照 | 移除补丁后完整重载并核对主模组数据，或重启 |
| 方块内容控制 | 不拦截通用放置，也不卸载已有 BlockEntity | 当作受支持资源／物品堆过滤，不是完整世界移除 |
| MTS 搜索半径 | 保存值可较小，但有效读取值至少为 32 | 不要依赖较小配置半径隔离附近载具 |
| 版本元数据 | gradle.properties 的 mod_version 是 1.0.0，mods.toml 的 version 是 1.0.1 | 用实际产物／提交识别版本，不单凭字符串推测发布顺序 |

本次 Wiki 更新记录这些问题，不修复这些游戏代码。相关行为详见[内容控制](内容控制)、[弹药覆写](弹药覆写)、[MTS兼容](MTS兼容)和[更新日志](更新日志)。

## [2] 会删除内容或容易误解的操作

两种扫描都会删除并重建 generated_scan/，同时移除旧 generated_scan.json。写入中断可能只留下部分新生成文件。普通扫描虽然生成关闭候选，也不是只读操作；手工规则和备份应放到生成目录之外。

载具 block_load 在对应实体加入世界时取消并丢弃，可能涉及从存档加载的实体。后来删除配置不能重建已经从保存状态中丢失的实体。

油桶按不可拆分的一桶转移。只要载具能接收任何能量，超出剩余容量的部分就可能浪费。油泵连接也不会跨重启持久保存。

## [3] 匹配与配置边界

空抛壳目标是广泛匹配，不同非空目标字段之间必须同时满足。外部文件不会天然高于数据包，扫描目录中的 JSON 备份仍会加载。

弹药比较可按提取的 ID 或完整规格命中，不是严格 NBT 身份比较。定义补丁不会将所有逐次发射条件都解释成临时条件修改。同优先级弹药替换规则会合并，而非只选择其中一条。

store 模式只用第一个点；空 ports 回退为一个点，不会关闭抛壳；count 为零会变成一；第一个点弹壳无效可能阻止整条掉落路径。击退 disabled 搭配正数 min 后也不再保证为零。

配置穿透零值不是对原生回退的否决；爆炸内圈也已开始衰减，并非平台区域。完整默认值和安全示例见各功能页。

## [4] 覆盖与集成限制

配方材料过滤在早期检查时保守保留带标签的路径，动态配方和自定义输出也可能不暴露足够信息。载具覆写只重建能识别的主模组装配配方类型。

计数弹壳合成依赖 ResultSlot.onTake 额外扣除弹壳。绕开该钩子的自动化机器和自定义界面，不会因序列化器存在就自动获得正确性保证。

伤害、自定义击退、反射式 MTS 辅助、可选 ECA 和视角钩子，都依赖真实调用路径。绕开这些路径的整合包行为可能不同，宽泛依赖范围不能证明后续内部接口仍兼容。

## [5] 配置分发与重载限制

服务端命令不下发客户端本地 JSON。配方表、资源管理器、外部规则和缓存 MTS 配置分别属于不同重载操作。成功返回加载数量不代表实际发射或配方命中，部署与验证见[推荐工作流](推荐工作流)。

## [6] 文档与测试状态

旧 Wiki 已原样保存在 docs/wiki-archive/2026-09-29，其中包含过时示例，不是当前格式参考。历史页面地址继续保留，正式页面已校正目标类型、目录名和源码行为。

文档校验检查页面覆盖、站内链接、引用源码路径和 JSON 语法，不运行 Minecraft，不解析实际物品注册表，不将每条生成规则与实际发射逐一匹配，也不证明数值平衡或所有模组组合兼容。
