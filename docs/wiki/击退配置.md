# 击退配置

[English](Knockback) | [配置总览](配置总览)

击退配置位于 format 5 抛壳规则文件内，分别控制受支持的**直击**与**爆炸**冲量通道。它不是伤害倍率，也不是通用物理行为覆写器。

---

## 只修改击退的完整示例

保存到 `config/superbaddon/shell_ejection/custom/controlled_knockback.json`：

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "knockback": {
        "direct": { "mode": "cap", "max": 0.2 },
        "explosion": { "mode": "cap", "max": 0.3 }
      }
    }
  ]
}
```

数值只是调节示例，不是默认平衡数值。规则不会改弹药或弹壳，也不会让原本不爆炸的弹射物变成爆炸弹。

<a name="channels"></a>
## [1] 两个通道

`knockback.direct` 对应受支持的非爆炸受击击退；`knockback.explosion` 对应受支持的自定义爆炸路径。任一通道都可省略，省略时在该配置中继承原始行为。

直击运行时代码需要补充缺失的自定义强度时，使用原版受击基准 `0.4`。它尊重卓越前线的 `NO_HURT_EFFECT` 抑制标签，不会盲目覆盖已经提供的自定义强度。目标抗性、其他钩子和实际伤害路径仍可能影响最终位移。

<a name="modes"></a>
## [2] 模式与 `value`

| 模式 | 应用上下限前的计算 | 必需字段 |
| --- | --- | --- |
| `inherit` | 保持原值 | 无 |
| `scale` | 原值 × value | `value` |
| `fixed` | 直接使用 value | `value` |
| `cap` | 保持原值，再限制上限 | `max` |
| `disabled` | 从零开始 | 无 |

默认是纯 `inherit`。未知模式、缺失必需数值或必需数值无效时，会警告并回退为 inherit。`value`、`min`、`max` 必须是有限、非负的 JSON 数值，不能填写百分比或数字字符串。

scale 为 0.5 表示将传入值减半，不是把伤害减半。fixed 设置的是冲量参数，不保证目标一定移动固定距离。

<a name="bounds"></a>
## [3] 上下限与执行顺序

代码先计算模式结果，再应用 `min`，随后应用 `max`，最后确保不小于零。应保持 `min <= max`，解析器不会替你建立合理的上下限区间。

> [!WARNING]
> `disabled` 不是最后无条件清零：正数 `min` 会把零重新抬高。需要关闭击退时，使用不带正数下限的 `{"mode":"disabled"}`。同理，带上下限的 inherit 是活动约束，不是纯继承。

## 完整的零冲量示例

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "knockback": {
        "direct": { "mode": "disabled" },
        "explosion": { "mode": "disabled" }
      }
    }
  ]
}
```

<a name="ammo"></a>
## [4] `by_ammo`

可选的 `knockback.by_ammo` 使用与抛壳相同的弹药规范化匹配。第一条匹配项按**整个通道**覆盖规则的基础配置。

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "knockback": {
        "direct": { "mode": "cap", "max": 0.3 },
        "explosion": { "mode": "cap", "max": 0.4 },
        "by_ammo": {
          "superbwarfare:rifle_ammo": {
            "direct": { "mode": "fixed", "value": 0.1 }
          }
        }
      }
    }
  ]
}
```

命中该弹药时，直击变成固定 0.1，爆炸仍保留基础上限。原直击通道的 max 不会继续合并进替换后的通道。弹药专用通道若是纯 inherit，会保留基础通道，不能单靠它把已受约束的基础配置重置为原版。示例键应按实际已选弹药身份确认。

<a name="scope"></a>
## [5] 规则选择与适用范围

击退独立选择第一条“目标匹配且所选配置不是全部纯继承”的规则，不需要同时有抛壳规则命中。一旦选中，就使用**整份配置**；省略的通道不会再从较低优先级规则分别补齐。

高优先级规则若只有纯 inherit，不会阻断较低优先级的活动击退配置。需要明确改变行为时，应填写实际有效的通道参数。

配置通过本附属支持的卓越前线弹射物和爆炸钩子附着。其他模组的弹射物、直接设置速度的代码、近战系统或绕开这些钩子的伤害路径，不会自动受控。因此，配置成功加载不等于完成了全局击退屏蔽。

<a name="tests"></a>
## [6] 重载与测试

外部文件使用 `/superbaddon shell_ejection reload_external`，数据包规则使用服务端 `/reload`，没有独立的 `knockback reload` 命令。

分别测试直击和爆炸，并保持目标、伤害、距离、弹药和目标抗性一致。随后用未被规则指定的武器做反向验证，确认匹配范围足够窄。伤害正确但位移不同，应检查实际伤害路径和其他自定义击退强度，不要把 cap 当成伤害配置。
