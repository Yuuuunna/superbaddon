# 常见问题

[English](FAQ) | [首页](首页)

需要按症状逐步定位时请看[故障排查](故障排查)。本页直接回答常见配置与工作流问题。

---

## 启动附属必须安装 MTS 或 Epic Core API 吗？

不需要。MTS 和 Epic Core API 使用受保护的可选集成入口。当前源码的必需依赖是受支持 Forge／Minecraft 环境中的 SuperbWarfare 和 GeckoLib。缺少必需依赖与某个可选功能不可用是两回事，详见[安装](安装)和[兼容性](兼容性)。

## 哪个配置目录才是正确的？

使用正在运行的实例或独立服务端工作目录下的 config/superbaddon/。旧名称 superbah6 不是当前活动配置命名空间。客户端和服务端可各有一份配置，修改其中一份不会自动分发到另一端，详见[配置目录结构](配置目录结构)。

## 为什么 JSON 加载成功却没有变化？

解析只说明加载器接受了数据。规则可能未启用、目标 ID 错误、优先级不足、座位／弹药条件不符，或修改后没有重载正确系统。扫描根元数据不能代替 rules[].enabled。建议先按[快速开始](快速开始)验证一个目标，再排查大型配置。

## 外部规则一定覆盖数据包吗？

不会。两者共同按优先级降序、规则 ID 升序排序；抛壳与击退独立选择适用规则，弹药覆写则有自己的 replace／append 合并方式。没有通用的“最后一个文件生效”规则，详见[抛壳配置](抛壳配置)和[弹药覆写](弹药覆写)。

## 怎么只停止抛壳，不禁用枪械？

使用启用状态、足够高优先级的匹配抛壳规则，设置 mode 为 none。关闭整条规则会让其他规则有机会匹配；把 count 设为零则会被限制为一。该操作不移除枪械或弹药，完整可回退示例见[快速开始](快速开始)。

## 普通 scan 能直接覆盖手工调整过的生成文件吗？

不能这样依赖它。两种扫描都会重建 generated_scan/ 并删除旧 generated_scan.json。普通模式虽生成关闭候选，仍会写入并重载。应先把手工规则移到 custom/，备份放到扫描目录外，详见[抛壳扫描命令](抛壳扫描命令)。

## 为什么 recipes_only 没有移除普通物品配方？

当前实现对载具装配输出处理了该模式，但普通物品／方块输出路径检查的是 block_load，存在源码确认的缺口。不要为了掩盖这一限制直接换成资源／实体阻止模式。普通配方应使用整合包已验证的只删配方方式，详见[配方禁用指南](配方禁用指南)。

## 加了单体覆写后，为什么载具的组设置不见了？

单体覆写整份替换组规格，省略字段随后使用原配方行为，而非继续继承组设置。确实需要保留的组字段，应在单体中重复填写。空 inputs 也不会禁用合成，详见[载具配方覆写](载具配方覆写)。

## 穿透设为零或关闭配置后，为何还有穿透？

配置查询仍可能回退到弹射物类型条目或弹射物自带穿透率。零值不是明确否决，enabled 也不会抹除原生穿透。实际查询顺序和伤害路径见[护甲穿透](护甲穿透)。

## MTS 为什么不认燃料、整桶消耗，或者不记忆倾斜视角？

默认零回退值拒绝未列出的燃料，显式零值也禁用对应燃料。油桶按不可拆分的一整桶转移，载具剩余容量不足时可能浪费多余燃料。倾斜视角明确只在当前会话生效，独立的输入桥接才会持久保存；两个客户端开关键默认都没绑定。详见[MTS兼容](MTS兼容)。

## 48 个弹壳拆成两格，为什么不能合成？

计数弹壳必须在同一格的一堆物品中达到要求，其他材料各占自己的格子。自动合成器若绕开结果格消耗钩子，需要单独测试，详见[弹壳复装](弹壳复装)。

## 删除规则再重载，就能撤销全部影响吗？

不一定。抛壳／击退规则表可被替换，但弹药补丁修改内存定义，没有通用原始快照；资源限制也可能已经改变持久存档状态。定义恢复应完整重载数据或重启并核对，持久状态改变时还要恢复世界备份，详见[推荐工作流](推荐工作流)。

## 这份 Wiki 是已实测兼容版本清单吗？

不是。Wiki 记录固定提交的源码核对和明确实现边界，依赖声明范围与可选集成保护不等于测试矩阵。报告问题时应提供实际 JAR 版本、配置和复现步骤。
