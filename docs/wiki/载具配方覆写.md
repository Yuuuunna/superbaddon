# 载具配方覆写

[English](Vehicle-Recipe-Override) | [配置总览](配置总览)

文件：`config/superbaddon/vehicle_recipe_override.json`。

本系统按 **`result.entity` 中的载具实体 ID** 改写既有卓越前线装配配方，可禁用配方、整体替换材料表、修改分类。它不会创建缺失配方、更换输出实体或注销载具。

---

## 完整示例

```json
{
  "groups": {
    "starter_aircraft": {
      "vehicles": ["superbwarfare:ah_6", "superbwarfare:a_10a"],
      "category": "aircraft",
      "inputs": ["8 minecraft:iron_block", "4 minecraft:redstone"]
    }
  },
  "overrides": {
    "superbwarfare:ah_6": {
      "inputs": ["4 minecraft:iron_block"]
    },
    "superbwarfare:tom_6": {
      "disabled": true
    }
  }
}
```

这些是示例成本，不是默认值。`groups` 和 `overrides` 默认都为空对象。

<a name="groups"></a>
## [1] 分组

组名是自行选择的对象键，`vehicles` 数组填写实体 ID；组内 `disabled`、`category`、`inputs` 组成一份共享规格。

一个载具同时出现在多个组中，会报告冲突并跳过有歧义的组覆写，而不是随意选择一个赢家。仍可用单体 override 显式处理该载具。不要依赖组的书写顺序解决冲突。

<a name="overrides"></a>
## [2] 单体覆写会整份替换组规则

`overrides` 是“载具 ID → 规格”的映射。单体规格替换的是**整份**组规格，不是仅覆盖出现的字段。

示例中 AH-6 使用单体材料表；其未填写的 category 来自原始配方，不会继承组里的 aircraft。单体仍需要某个组字段时，请显式重复填写。单体空对象也可阻止采用组规格，而不改变原始配方。

同一实体输出的所有匹配装配配方都可能受影响。键不是配方 ID，也不是容器物品 ID。

<a name="disabled"></a>
## [3] `disabled`

布尔值，默认 false。true 从最终配方表中移除匹配的装配配方，不阻止已经存在或通过管理方式生成的载具加入世界。

删除先于材料／分类改写执行。被禁用配方不会因为同时提供 inputs 而恢复；被内容控制移除的配方也不能靠覆写复活。

<a name="category"></a>
## [4] `category`

可选字符串，支持 `land`、`defense`、`aircraft`、`civilian`、`water`、`misc`，会规范化为小写。最终选中的规格中省略该字段，就保留原始配方分类。

无效分类会警告并忽略，不会创建新分类。这里是装配界面分类，不是实体类型或标签。

<a name="inputs"></a>
## [5] `inputs`

可选的**非空字符串数组**，整体替换材料表，使用主模组载具装配材料语法：

| 字符串示例 | 含义 |
| --- | --- |
| `minecraft:iron_ingot` | 一个物品材料 |
| `8 minecraft:iron_block` | 指定数量的物品材料 |
| `3 #superbwarfare:storage_blocks/steel` | 指定数量的标签材料，前提是该标签实际存在 |

数量应为正数，物品和标签应实际存在。语法通过不代表标签一定含有物品。这里不是 NBT 对象，也不是普通合成配方的材料对象格式。

空数组**不表示禁用，也不表示免费制造**，它不会成为有效的材料覆写。任意条目无效时，整份替换材料字段被丢弃，不会部分应用；其他独立有效的 disabled 或 category 仍可能生效。要禁用配方请明确写 `disabled: true`。

<a name="reload"></a>
## [6] 重载与兼容顺序

修改后执行服务端 `/reload` 或重启。配方重写监听器位于配方管理器加载之后，处理最终反序列化的配方表，设计上包括 KubeJS 已改写的结果。它重载内容控制和载具覆写，先删除被禁配方，再重建幸存的匹配载具配方，只改材料／分类，保留 ID 与输出。

仅执行 `/superbaddon content_control reload` 不会运行该配方重写，也没有独立的载具配方重载命令。这里说明的是实现设计，不是对所有 KubeJS 或附属版本的兼容实测保证。

检查日志中的 `Loaded SuperbAddon vehicle recipe overrides`、`[vehicle-recipe-override] applied`，以及“配置存在但匹配到零个配方”的警告。先验证一个载具的装配界面和实际材料扣除。回退时删除单体／组条目，再从原始数据包完整重载配方。
