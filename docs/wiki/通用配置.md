# 通用配置

[English](Common-Configuration) | [配置总览](配置总览)

本页说明不同配置系统共用的编辑原则，**不是在介绍名为 `common.json` 的文件**。当前也不存在一个能关闭本附属全部功能的统一 `enabled` 总开关。

---

## [1] 使用明确、有效的 JSON

使用 UTF-8 编码、带双引号的属性名、JSON 布尔值 `true`／`false`，并在需要数值的位置填写数值。避免重复键、尾逗号和编程语言式注释。部分解析器可能宽松接收或忽略额外内容，但不要把这种容错当成通用格式约定。

使用 `superbwarfare:ah_6` 这样的完整注册 ID，不要用显示名、中文翻译、猜测的容器名或文件名替代。ID 应保持小写；语法有效不代表游戏中一定注册了对应物品或实体。

加载器忽略的 `_note`、`comment` 等元数据仅供阅读，不能用来代替真正的行为字段。

## [2] 分清修改的是哪个 `enabled`

| 位置 | 含义 |
| --- | --- |
| `rules[].enabled` | 是否加载这一条规则；省略时为 true |
| `rules[].ammo_override.enabled` | 是否启用该规则的弹药补丁，还要求 `allowed` 非空；省略时为 false |
| `armor_penetration.json` 的 `enabled` | 是否启用配置的穿透查询 |
| `mts_compat.json` 的 `enabled` | 控制燃料兼容，不代替独立的输入桥接／视角开关 |
| 抛壳根对象的 `enabled_by_default` | 扫描元数据；当前解析器不会把它读取为规则默认值 |

内容控制使用每个目标的模式字符串；载具装配禁用使用措辞相反的 `disabled`。不要将一个格式中的开关原样搬到另一个格式中。

## [3] 单位与模式不能混用

弹壳 `chance` 使用 0–1 概率，`pickup_delay` 以 tick 为单位，偏移使用发射坐标基准。击退值是非负的冲量控制参数，不是伤害百分比。护甲穿透使用 0–1 比例或带引号的百分比，如 `"35%"`。MTS 转换值是每桶，也就是每 1000 mB 的能量。

`ejection.mode: "none"` 用于让选中的规则不生成弹壳；`knockback.direct.mode: "disabled"` 用于把对应直击冲量设为零。两种模式名不可互换。

## [4] “重载”不是同一个操作

外部规则重载会更新规则表、应用活动弹药补丁并刷新内容控制查询状态，但不会重载所有服务端数据包、重建配方表、刷新客户端资产或重读所有独立配置。

配方使用服务端 `/reload` 或重启；护甲穿透使用专用命令；客户端资源变化和 MTS 文件修改应重启对应实例。仅重载客户端资源，不代表缓存中的本地 JSON 必然被重读。

完整操作对照见[配置总览](配置总览)，实际注册的命令见[命令参考](命令参考)。

## [5] 每种功能的优先级规则不同

抛壳与击退分别在“优先级降序、规则 ID 升序”的列表中选择第一条适用规则。弹药补丁则合并最高优先级的替换集合，再加入追加项。载具单体配方覆写整份替换组规则。资源过滤条件又是从独立的内容控制表派生。

不能假设通用的“后面的文件覆盖前面的文件”。应明确分配优先级，除非理解合并方式，否则避免多条同优先级规则同时匹配相同情形。

## [6] 安全分发与回退

把干净备份放到扫描目录之外。每次只做一个逻辑变化，重载正确系统，检查日志，再分别测试“应该匹配”和“不应该匹配”的情况，并记录版本和目标 ID。

删除弹药覆写后，外部文件重载没有通用的原始数据还原步骤。应重启，或者完整重载主模组数据并验证结果。命令返回加载了规则，只能证明解析完成，不代表实际发射或配方已经命中。
