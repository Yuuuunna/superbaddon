# 资源裁剪指南

[English](Resource-Trimming-Guide) | [内容控制](内容控制)

资源裁剪面向明确要排除受支持内容及相关数据／资产的整合包作者。它不是清理磁盘、删除注册表或保证某个内存节省比例的功能。

---

## [1] 先选择影响最小的方式

只想改变合成获取渠道，优先使用[配方控制](配方禁用指南)；只想改武器行为，使用抛壳／弹药／击退规则。只有确实要同时限制受支持资源与运行时入口时，才使用 block_load。

请在存档副本中操作，保留未改动的双端配置和世界备份。已有载具可能在加载时被拒绝，已有方块则可能继续运行但失去资源。视觉上消失不等于存档迁移安全。

## [2] 配置注册目标，不要填写任意路径

一个完整最小示例：

```json
{
  "items": { "superbwarfare:taser": "block_load" },
  "vehicles": {},
  "blocks": {},
  "worldgen_ores": { "superbwarfare": false }
}
```

保存到 config/superbaddon/content_control.json，并确认目标确实存在。代码从注册 ID 派生资源过滤规则，没有接受任意文件系统路径或目录删除命令的配置字段。

## [3] 派生资源布局

对 namespace:path 目标，过滤始终限定在同一命名空间。下表表示相关命名空间中的资源管理器路径，不是从 JAR 实际删除的文件。

| 目标 | 精确匹配 | 前缀族，每项后接 `/path` |
| --- | --- | --- |
| 物品／枪械 | `sbw/guns/path.json` | `models/item`、`models/displaysettings`、`textures/item`、`textures/gun_icon`、`geo`、`geo/lod`、`animations` |
| 载具 | `sbw/vehicles/path.json` | `textures/vehicle_icon`、`geo`、`geo/lod`、`animations`、`textures/entity`、`textures/bedrock/vehicle`、`textures/bedrock/vehicle_lod`、`models/bedrock/vehicle`、`models/bedrock/vehicle_lod`、`animations/bedrock/vehicle`、`sounds/vehicle` |
| 方块 | `loot_tables/blocks/path.json` | `blockstates`、`models/block`、`models/item`、`models/bedrock/block`、`textures/block`、`textures/bedrock/block`、`textures/item`、`textures/entity`、`textures/gui` |

前缀规则匹配完全相同的路径，或后续以 `/`、`.`、`_` 开始的路径。因此 foo_bar 可归入 foo 资源族，而不相关的 foobar 不会仅因前几个字符相同就被匹配。但共享资产命名仍可能让看似单一的目标影响另一模型。

这不是删除整个命名空间，也不会自动识别其他模组关联该 ID 的全部资源。固定映射覆盖已知主模组布局，包括旧 GeckoLib 与较新的 bedrock 载具目录；其他内容布局仍需单独验证。

## [4] 保留基础设施

vehicle_assembling_table 与 container 路径在核心资源／物品堆／实体裁剪查询中跨命名空间受保护，不应通过猜测别名绕开保护。每次裁剪一批内容后，都应检查装配设施、容器和保留载具的渲染。

物品的 _blueprint 处理可能跟随本体枪械模式；载具容器通过 EntityType NBT 确定身份，不是每个载具有独立容器物品 ID。检查背包和创造栏结果时应考虑这些派生关联。

## [5] 矿物生成范围

打包的生物群系修改器在 worldgen_ores.superbwarfare 为 true 时启用，作用于主世界生物群系标签的地下矿石生成阶段，移除卓越前线的六种特征：银矿、深层银矿、方铅矿、深层方铅矿、白钨矿和深层白钨矿。

它控制的是这组生成特征，不是所有维度的一切矿石。不会移除已有方块、注销矿石物品，也不会因新增一个任意命名空间键就产生兼容。应重启后在测试世界的新地形中验证，而不是删除正式世界区块来测试。

## [6] 分发与验收

将一致的内容／资源配置分发到服务端和相关客户端，服务端命令不会自动下发这些本地文件。重启对应实例，让缓存配置和资源管理器一起重新建立。

检查目标受支持的使用、渲染、掉落和配方入口，再检查保留基础设施及可能共享前缀的资产。保存、退出并重新打开测试世界，暴露实体加载影响。对于方块，明确验证使用者没有把裁剪误认为禁止放置或删除 BlockEntity。

性能应在同一整合包和硬件上，用可重复的前后对照测量启动时间、内存或帧耗时。存在过滤器本身不能证明具体幅度的性能提升。

## [7] 回退

恢复原内容配置并重启，可以恢复资源访问，但不能重建已经丢弃并保存进世界状态的实体、已消耗物品或其他持久变化。测试改变了存档状态时，应同时恢复世界备份。
