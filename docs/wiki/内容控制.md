# 内容控制

[English](Content-Control) | [配置总览](配置总览)

内容控制只从以下文件读取：

```text
config/superbaddon/content_control.json
```

它控制受支持的配方、资源访问以及部分物品／实体入口，**不会删除注册表条目，也不是拦截所有相关行为的通用禁用器**。

---

## 完整示例

以下示例会实际限制内容，请先在存档副本中测试。

```json
{
  "_note": "Example only: review every target before enabling",
  "items": {
    "superbwarfare:taser": "block_load"
  },
  "vehicles": {
    "superbwarfare:ah_6": "recipes_only"
  },
  "blocks": {
    "superbwarfare:charging_station": "block_load"
  },
  "worldgen_ores": {
    "superbwarfare": true
  }
}
```

<a name="items"></a>
## [1] `items`

这是“物品注册 ID → 模式字符串”的对象。填写枪械／物品的注册 ID，而不是显示名称。对应的 `<gun>_blueprint` 物品会归入枪械本体的模式，除非存在更具体且被保留的配置条目。

`block_load` 会参与被禁用物品堆查询、创造栏过滤、掉落物拒绝、配方过滤以及物品／枪械资源过滤。它不保证清空所有已有背包，也不保证拦截其他模组实现的每一种自定义交互。

默认 `items` 为空。移除条目或设置 `keep` 表示不施加该条独立限制，但共享资源或其他目标的规则仍可能产生影响。

<a name="vehicles"></a>
## [2] `vehicles`

键是**载具实体注册 ID**，例如 `superbwarfare:ah_6`，不要猜测一个 `ah_6_container` 物品 ID。载具容器物品通过方块实体 NBT 中的 `EntityType` 判断所属载具。

`recipes_only` 移除匹配的载具装配输出，不阻止实体、不裁剪资产。`block_load` 还会派生载具资源过滤器、阻止匹配的容器物品堆，并在对应载具实体加入世界时取消加入、丢弃实体。

> [!WARNING]
> 实体加入事件也可能涉及从存档加载的实体。因此，不能把 `block_load` 当成已经放置载具的可逆隐藏开关。在重要世界测试前必须备份，并验证保存、退出和重新加载后的行为。

<a name="blocks"></a>
## [3] `blocks`

键是方块注册 ID。实现假定对应 BlockItem 使用相同 ID。`block_load` 会添加方块状态、模型、纹理、界面和方块掉落表的资源过滤，并参与物品堆、相关配方和创造栏过滤。

它**不拦截通用方块放置，也不会卸载已有 BlockEntity**。已经放置的方块可能仍在执行逻辑，却失去资源或正常掉落表。因此，这不是从旧世界安全移除任意机器的通用办法。

<a name="modes"></a>
## [4] 模式与实际边界

| 模式 | 资源／实体限制 | 当前源码中的配方行为 |
| --- | --- | --- |
| `keep` | 不施加该条限制 | 不施加该条限制 |
| `recipes_only` | 不裁剪、不拦截 | 载具装配输出已处理；普通物品／方块输出存在已知缺口 |
| `block_load` | 受支持的资源与物品堆／实体检查 | 过滤受支持的被禁输出和明确必需的被禁物品输入，不保证覆盖所有自定义配方 |

只识别以上模式；未知字符串回退为 `keep`。不要使用 `disabled`、`remove` 或 `true` 代替模式名。

普通配方输出走的是 `blocksItemStack`，该查询检查 `block_load`，不会按 `recipes_only` 判定。这是从源码确认的实现限制，不应直接归咎于使用者 JSON 写错。普通物品只删配方时，应选择适合的配方数据包／脚本方式，并检查最终配方表，详见[配方禁用指南](配方禁用指南)。

`vehicle_assembling_table` 和 `container` 这两个路径是跨命名空间保护的基础设施。资源及实体／物品堆检查会避免裁掉它们；这种保护不代表所有配方分支都无条件豁免。不要把这些基础设施当成普通目标批量移除。

<a name="ores"></a>
## [5] `worldgen_ores`

默认是 `{"superbwarfare": false}`。改为 true 后，通过打包的生物群系修改器移除受支持的卓越前线矿物生成特征。

这不会注销矿石方块或物品，也不会删除已有矿石、重新生成旧区块。虽然解析器接收命名空间键，但添加任意其他命名空间，并不会自动生成对应模组矿石的移除规则。

<a name="reload"></a>
## [6] 重载与验证

`/superbaddon content_control reload` 会重读文件并重建查询状态与资源过滤器，但不会自行重跑配方改写，也不会重载客户端资源。

配方变化使用服务端 `/reload` 或重启。资源裁剪应对齐双端配置并重启对应实例。矿物生成变化应重启后在测试世界的新地形中检查，不能用旧区块中的矿石判断是否生效。

验证时既要检查目标限制，也要检查保留内容：装配台、容器渲染、无关配方、附近机器，以及存档重新加载。日志中的目标数量和被移除配方 ID 可用于定位，但解析成功不等于验收通过。

## 资源布局与输入配方过滤

资源路径由代码派生，本文件不接收任意资源文件删除列表。过滤器只作用于同一命名空间，并遵循[资源裁剪指南](资源裁剪指南)说明的固定布局。

当某个必需材料完全由明确被禁的物品候选组成时，配方可能被移除；若材料中包含标签，当前阶段会保守保留，而不是强行解析尚未完整绑定的标签。动态配方也可能不暴露完整输出或材料。这些边界详见[已知问题](已知问题)。
