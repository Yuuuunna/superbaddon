# Content Control

[简体中文](内容控制) | [Configuration](Configuration)

`content_control.json` 用于控制 SuperbWarfare 的物品、载具、方块和矿物生成。

配置文件位置：

```text
config/superbaddon/content_control.json
```

首次启动 SuperbAddon 后，如果文件不存在，模组会自动生成一个空配置。

> [!IMPORTANT]
> `block_load` 不会把内容从 Forge 注册表中注销。
>
> Forge 完成注册后，物品、方块和实体类型不能通过普通配置动态删除。SuperbAddon 实际执行的是配方删除、资源过滤、创造栏过滤和运行时拦截。

---

## Complete configuration example

点击配置行末尾的编号，可以跳转到对应说明。

<pre>
{
  "_note": "SuperbAddon content control example",              <a href="#note">[1]</a>
  "items": {                                                   <a href="#items">[2]</a>
    "superbwarfare:ak_47": "recipes_only",                     <a href="#item-target">[3]</a> <a href="#recipes-only">[4]</a>
    "superbwarfare:taser": "block_load"                        <a href="#item-target">[3]</a> <a href="#block-load">[5]</a>
  },
  "vehicles": {                                                <a href="#vehicles">[6]</a>
    "superbwarfare:ah_6": "block_load"                         <a href="#vehicle-target">[7]</a> <a href="#block-load">[5]</a>
  },
  "blocks": {                                                  <a href="#blocks">[8]</a>
    "superbwarfare:charging_station": "block_load"             <a href="#block-target">[9]</a> <a href="#block-load">[5]</a>
  },
  "worldgen_ores": {                                           <a href="#worldgen-ores">[10]</a>
    "superbwarfare": true                                      <a href="#worldgen-namespace">[11]</a>
  }
}
</pre>

这份样例会：

- 尝试移除 AK-47 的相关配方，但保留武器本身。
- 对 Taser 执行 `block_load`。
- 对 AH-6 载具执行 `block_load`。
- 对 Charging Station 方块执行 `block_load`。
- 禁用 SuperbWarfare 内置矿物在新生成区块中的生成。

<a name="note"></a>

## [1] `_note`

```json
"_note": "SuperbAddon content control example"
```

`_note` 只是给配置维护者阅读的说明文字。

它不会参与配置解析，可以修改或删除。

标准 JSON 不支持以下注释：

```json
{
  // Invalid JSON
  "items": {}
}
```

需要记录说明时，应使用 `_note` 或其他普通字符串字段。

---

<a name="items"></a>

## [2] `items`

```json
"items": {
  "superbwarfare:ak_47": "recipes_only",
  "superbwarfare:taser": "block_load"
}
```

`items` 用于控制枪械和普通物品。

基本格式：

```json
"items": {
  "<namespace>:<item_id>": "<mode>"
}
```

例如：

```json
"items": {
  "superbwarfare:taser": "block_load"
}
```

`items` 中的键必须是物品注册 ID，而不是游戏内显示名称。

错误：

```json
"items": {
  "Taser": "block_load"
}
```

正确：

```json
"items": {
  "superbwarfare:taser": "block_load"
}
```

---

<a name="item-target"></a>

## [3] Item target

```json
"superbwarfare:ak_47": "recipes_only"
```

冒号左侧是目标物品的注册 ID：

```text
superbwarfare:ak_47
```

注册 ID 由两部分组成：

```text
namespace:path
```

在这个例子中：

```text
namespace = superbwarfare
path      = ak_47
```

配置加载时会：

- 删除首尾空格。
- 转换为小写。
- 检查是否为合法的 Minecraft ResourceLocation。

例如：

```json
"  SUPERBWARFARE:AK_47  ": "block_load"
```

会被规范化为：

```text
superbwarfare:ak_47
```

无法解析的注册 ID 会被忽略，并在日志中输出警告。

### Blueprint inheritance

枪械条目会自动应用到同名蓝图。

例如：

```json
"items": {
  "superbwarfare:ak_47": "block_load"
}
```

也会影响：

```text
superbwarfare:ak_47_blueprint
```

通常不需要再写一遍：

```json
"items": {
  "superbwarfare:ak_47": "block_load",
  "superbwarfare:ak_47_blueprint": "block_load"
}
```

<a name="recipes-only"></a>

## [4] `recipes_only`

```json
"superbwarfare:ak_47": "recipes_only"
```

`recipes_only` 的设计目标是只移除目标配方，不裁剪目标内容。

它不会：

- 过滤模型。
- 过滤纹理。
- 从创造栏隐藏物品。
- 阻止物品实体生成。
- 阻止载具实体生成。
- 删除已经存在的物品或载具。
- 从 Forge 注册表注销目标。

### 当前版本的重要限制

当前源码中，`recipes_only` 对载具装配配方的匹配最可靠。

载具装配配方会直接暴露最终载具实体 ID，因此以下配置可以正确匹配 AH-6：

```json
{
  "vehicles": {
    "superbwarfare:ah_6": "recipes_only"
  }
}
```

但是，普通物品和普通方块配方的输出检查当前主要通过 `block_load` 判定。

因此：

```json
{
  "items": {
    "superbwarfare:ak_47": "recipes_only"
  }
}
```

以及：

```json
{
  "blocks": {
    "superbwarfare:charging_station": "recipes_only"
  }
}
```

不保证能删除所有普通配方。

修改后必须执行：

```mcfunction
/reload
```

并在 JEI、装配台和日志中确认最终结果。

对于载具配方，优先使用：

```text
config/superbaddon/vehicle_recipe_override.json
```

详见 [[Vehicle-Recipe-Override|Vehicle Recipe Override]]。

<a name="block-load"></a>

## [5] `block_load`

```json
"superbwarfare:taser": "block_load"
```

`block_load` 是当前最强的内容控制模式。

它会根据目标类型执行：

- 删除支持的配方。
- 过滤关联资源。
- 从创造栏过滤目标物品。
- 拦截部分目标物品实体。
- 拦截部分目标载具实体。
- 阻止部分数据文件被资源管理器读取。

`block_load` 仍然不会：

- 注销 Forge 注册项。
- 重写所有现有区块。
- 自动清理所有容器中的旧物品。
- 自动删除所有存档 NBT 引用。
- 保证第三方模组无法再次引用目标 ID。

可将它理解为：

```text
尽可能阻止目标继续被正常使用和加载
```

而不是：

```text
从游戏注册表中彻底删除目标
```

---

<a name="vehicles"></a>

## [6] `vehicles`

```json
"vehicles": {
  "superbwarfare:ah_6": "block_load"
}
```

`vehicles` 用于控制载具实体类型。

基本格式：

```json
"vehicles": {
  "<namespace>:<vehicle_entity_id>": "<mode>"
}
```

这里填写的是载具实体注册 ID，不是载具配方 ID，也不是容器物品的显示名称。

---

<a name="vehicle-target"></a>

## [7] Vehicle target

```json
"superbwarfare:ah_6": "block_load"
```

`superbwarfare:ah_6` 必须对应载具实体类型。

错误：

```json
"vehicles": {
  "superbwarfare:ah_6_container": "block_load"
}
```

正确：

```json
"vehicles": {
  "superbwarfare:ah_6": "block_load"
}
```

SuperbAddon 会读取载具容器物品中的：

```text
EntityType
```

并根据该值判断容器对应的载具。

对载具使用 `block_load` 时，SuperbAddon会尝试：

- 删除对应的载具装配配方。
- 过滤对应载具容器物品。
- 从创造栏移除载具容器。
- 阻止该载具实体加入世界。
- 过滤载具数据文件。
- 过滤载具图标。
- 过滤 GeckoLib 模型。
- 过滤 GeckoLib LOD 模型。
- 过滤载具动画。
- 过滤载具纹理。
- 过滤 Bedrock 载具模型。
- 过滤 Bedrock LOD 模型。
- 过滤 Bedrock 载具纹理。
- 过滤对应载具声音。

载具实体类型仍然存在于 Forge 注册表中。

命令、脚本或已有区块仍然可能引用该 ID，但实体尝试加入世界时会被当前运行时拦截。

---

<a name="blocks"></a>

## [8] `blocks`

```json
"blocks": {
  "superbwarfare:charging_station": "block_load"
}
```

`blocks` 用于控制方块及其同名 BlockItem。

基本格式：

```json
"blocks": {
  "<namespace>:<block_id>": "<mode>"
}
```

当前实现假设：

```text
方块注册 ID = BlockItem 注册 ID
```

---

<a name="block-target"></a>

## [9] Block target

```json
"superbwarfare:charging_station": "block_load"
```

对方块使用 `block_load` 时，SuperbAddon会尝试过滤：

- `blockstates/<id>`
- `models/block/<id>`
- `models/item/<id>`
- `models/bedrock/block/<id>`
- `textures/block/<id>`
- `textures/item/<id>`
- `textures/bedrock/block/<id>`
- `textures/entity/<id>`
- `textures/gui/<id>`
- `loot_tables/blocks/<id>.json`

同时可能：

- 从创造栏移除同名 BlockItem。
- 拦截掉落到世界中的同名 BlockItem。
- 删除输出该 BlockItem 的支持配方。
- 删除对应方块掉落表。

当前版本不会：

- 删除世界中已经放置的方块。
- 明确阻止玩家放置方块。
- 明确阻止 BlockEntity 创建。
- 从方块注册表注销方块。
- 自动重写已有区块。

因此，以下配置：

```json
{
  "blocks": {
    "superbwarfare:charging_station": "block_load"
  }
}
```

不代表已生成世界中的 Charging Station 会自动消失。

资源裁剪应在正式创建和分发存档前完成。

---

<a name="worldgen-ores"></a>

## [10] `worldgen_ores`

```json
"worldgen_ores": {
  "superbwarfare": true
}
```

`worldgen_ores` 用于启用按命名空间控制的矿物生成移除条件。

基本格式：

```json
"worldgen_ores": {
  "<namespace>": true
}
```

这里只接受真正的 JSON 布尔值。

正确：

```json
"superbwarfare": true
```

错误：

```json
"superbwarfare": "true"
```

字符串 `"true"` 不会被当作布尔值处理。

---

<a name="worldgen-namespace"></a>

## [11] World-generation namespace

```json
"superbwarfare": true
```

当前 SuperbAddon 内置的 Biome Modifier 只针对 SuperbWarfare 的以下世界生成特征：

```text
superbwarfare:silver_ore
superbwarfare:deepslate_silver_ore
superbwarfare:galena_ore
superbwarfare:deepslate_galena_ore
superbwarfare:scheelite_ore
superbwarfare:deepslate_scheelite_ore
```

启用：

```json
"superbwarfare": true
```

会在支持的世界生成阶段移除这些特征。

它不会：

- 删除已经生成区块中的矿石。
- 删除矿石方块。
- 删除矿石物品。
- 注销矿石注册项。
- 自动扫描并删除其他模组的矿物。

以下配置：

```json
"another_mod": true
```

不会自动移除 `another_mod` 的所有矿物。

只有其他数据包或模组明确使用 SuperbAddon 的世界生成条件时，该命名空间配置才可能产生作用。

---

## `keep`

完整模式列表是：

```text
keep
recipes_only
block_load
```

`keep` 表示不干预目标。

例如：

```json
{
  "items": {
    "superbwarfare:repair_tool": "keep"
  }
}
```

等效于：

```json
{
  "items": {}
}
```

配置解析完成后，`keep` 条目不会进入运行时控制表。

如果没有必要记录该目标，直接删除对应条目即可。

---

## Invalid modes

只有以下三个字符串有效：

```text
keep
recipes_only
block_load
```

错误：

```json
{
  "items": {
    "superbwarfare:ak_47": "disabled"
  }
}
```

`disabled` 不是合法模式，因此会被当作 `keep`。

其他无效值同样不会生效：

```text
disable
blocked
remove
true
false
off
unload
```

模式名称必须完全使用文档规定的值。

---

## Recipe dependency filtering

`block_load` 除了检查配方输出，还会检查部分配方输入。

例如：

```json
{
  "items": {
    "superbwarfare:taser": "block_load"
  }
}
```

当某个配方材料槽只包含被阻止的物品时，该配方可能被删除。

例如只接受 Taser 的材料：

```json
{
  "item": "superbwarfare:taser"
}
```

但是，带有通用标签的材料不会被视为完全阻止：

```json
{
  "tag": "forge:tools"
}
```

原因是该标签可能同时包含：

- 被阻止物品。
- 未被阻止物品。
- 其他模组提供的替代物品。

SuperbAddon不会因为一个大型共享标签中包含某个被阻止物品，就删除所有使用该标签的配方。

---

## Protected infrastructure

以下 path 被视为 SuperbWarfare 基础设施：

```text
vehicle_assembling_table
container
```

保护按 path 判断，不局限于 `superbwarfare` 命名空间。

这些内容不能按照普通物品或载具进行完整资源裁剪，因为它们被多个功能共同使用。

例如：

```json
{
  "blocks": {
    "superbwarfare:vehicle_assembling_table": "block_load"
  }
}
```

不是禁用所有载具的正确方式。

直接裁剪装配台或共享容器可能破坏：

- 载具装配界面。
- 载具容器物品。
- 载具渲染器。
- 未被禁用的其他载具。

要禁用单个载具，应写：

```json
{
  "vehicles": {
    "superbwarfare:ah_6": "block_load"
  }
}
```

只想禁用载具配方时，应使用：

```text
config/superbaddon/vehicle_recipe_override.json
```

## Applying changes

修改：

```text
config/superbaddon/content_control.json
```

后，推荐执行：

```mcfunction
/reload
```

`/reload` 会重新建立最终配方表，并再次应用 Content Control。

也可以执行：

```mcfunction
/superbaddon content_control reload
```

该命令会：

- 重新读取 `content_control.json`。
- 更新 Content Control 内存状态。
- 显示已读取的物品数量。
- 显示已读取的载具数量。
- 显示生成的资源过滤器数量。
- 显示被禁用的矿物命名空间数量。

但是该命令不会单独重建所有已经加载的系统。

根据修改内容，仍然可能需要：

- `/reload`
- 客户端资源重载。
- 重新进入世界。
- 重启客户端。
- 重启服务端。

使用 `block_load` 后，最稳妥的方法是同时重启客户端和服务端。

---

## Client and server distribution

Content Control 同时影响服务端逻辑和客户端资源。

服务端可能处理：

- 配方过滤。
- 载具实体加入世界。
- ItemEntity 加入世界。
- 世界生成条件。

客户端可能处理：

- 模型过滤。
- 纹理过滤。
- 动画过滤。
- 图标过滤。
- 声音过滤。
- 创造栏过滤。

整合包应向客户端和服务端分发相同的：

```text
config/superbaddon/content_control.json
```

只修改服务端文件，无法自动删除客户端已经加载的模型和纹理。

---

## Existing worlds

Content Control 不会自动清理所有旧数据。

已有世界中可能继续存在：

- 玩家背包里的旧物品。
- 箱子和机器里的旧物品。
- 已经放置的方块。
- 区块中保存的载具 NBT。
- 任务系统中引用的物品 ID。
- KubeJS 脚本中引用的内容。
- 命令方块中引用的实体 ID。

大规模修改 `block_load` 前，应先备份存档并在测试世界中验证。

## Troubleshooting

### Configuration file has no effect

确认文件路径是：

```text
config/superbaddon/content_control.json
```

不要放入：

```text
config/superbaddon/shell_ejection/
```

执行：

```mcfunction
/reload
```

然后检查 `latest.log` 中是否出现：

```text
Loaded SuperbAddon content control
```

---

### A target is ignored

确认目标使用完整注册 ID：

```text
namespace:path
```

错误：

```json
"ak_47": "block_load"
```

正确：

```json
"superbwarfare:ak_47": "block_load"
```

---

### A mode is ignored

确认模式是以下三个值之一：

```text
keep
recipes_only
block_load
```

错误：

```json
"superbwarfare:ak_47": "disable"
```

正确：

```json
"superbwarfare:ak_47": "block_load"
```

---

### A blocked block still exists

`block_load` 不会删除已经放置的方块。

它也不会从 Forge 注册表注销该方块。

该方块仍可能保留在已有区块中。

---

### A blocked vehicle remains in save data

载具实体类型仍然存在于注册表中。

旧区块和外部脚本仍可能引用该 ID。

SuperbAddon只会在支持的载具实体加入世界阶段取消它，不会批量重写所有区块文件。

---

### A recipe is still visible

执行：

```mcfunction
/reload
```

然后重新检查最终配方表。

对于普通物品和方块，当前版本的 `recipes_only` 不保证匹配所有配方序列化器。

对于载具装配配方，建议改用：

```text
config/superbaddon/vehicle_recipe_override.json
```

例如：

```json
{
  "groups": {},
  "overrides": {
    "superbwarfare:ah_6": {
      "disabled": true
    }
  }
}
```
