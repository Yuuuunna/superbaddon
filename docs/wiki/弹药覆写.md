# 弹药覆写

[English](Ammunition-Overrides) | [抛壳配置](抛壳配置)

`ammo_override` 修改卓越前线的枪械或载具武器弹药定义。它本身不会选择弹壳、修改弹射物伤害，也不会注册新弹药物品。

---

## 完整示例

放入外部 format 5 文件。启用前确认安装环境中存在对应枪械和弹药。

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "ammo_override": {
        "enabled": true,
        "policy": "replace",
        "allowed": ["superbwarfare:rifle_ammo"]
      }
    }
  ]
}
```

<a name="activation"></a>
## [1] 激活条件

所属规则必须启用。`ammo_override.enabled` 默认 **false**，且只有该开关为 true、`allowed` 中至少存在一个有效非空选项时才会成为活动覆写。

空 `allowed` 不表示“禁止装填所有弹药”，而是使该覆写不活动。关闭弹药覆写时，同一规则的抛壳或击退部分仍可以工作。

<a name="policy"></a>
## [2] `policy` 与合并

推荐取值为 `replace`（默认）和 `append`。只有字符串 `append` 会选择追加，其他字符串会回退为 replace，因此拼写错误可能造成实质影响。

补丁器按每个枪械或载具武器目标收集定义修改，保留**替换规则中的最高优先级**，合并所有处于这一优先级的 replace 允许项，然后加入 append 选项。更低优先级的 replace 不参与合并；append 则独立于替换优先级进行收集。

这不是抛壳系统的“第一条匹配规则获胜”。两条同优先级 replace 可能共同扩大允许弹药集合，而非彼此覆盖。去重依据规范化后的规格／ID，枪械消费者与载具原始数据的去重细节也有差别；不要用重复项编码不同弹药变体。

<a name="ammo"></a>
## [3] `allowed` 条目格式

推荐使用数组，条目来自扫描器导出的实际规格，或主模组明确支持的弹药消费者格式。解析器也兼容直接提供单个选项。

字符串支持主模组消费者语法，例如可选的数量和受支持的 `@`／`#` 前缀。不要猜测标签或虚拟弹药标识符；只有确实需要物品消费者时，单纯的物品 ID 才合适。

对象形式可以保留主模组消费者数据：

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "ammo_override": {
        "enabled": true,
        "policy": "append",
        "allowed": [
          {
            "ammo": "superbwarfare:rifle_ammo",
            "consumer": { "Ammo": "superbwarfare:rifle_ammo" }
          }
        ]
      }
    }
  ]
}
```

`consumer` 会交给卓越前线的消费者反序列化器，不是可以随意填写的物品堆对象。外层身份先从 `ammo`、`Ammo`、`id`、`Id` 读取，再尝试消费者中的字段。没有嵌套 consumer 时，对象本身会在移除 casing／comment 元数据后作为消费者。不了解主模组格式时，应保留扫描导出的消费者属性。

弹药身份比较会规范化大小写和空白，可按提取的 ID 或完整规格命中，不是严格 NBT 区分器。MTS 弹药盒行为见[MTS兼容](MTS兼容)。

<a name="targets"></a>
## [4] 修改目标是定义，不是逐次发射条件

活动覆写必须显式具有 `target.guns` 或 `target.vehicles`。只填写弹射物目标，不会应用弹药定义补丁。

枪械补丁直接针对列出的枪械定义。载具补丁针对列出的载具，可进一步限制从 0 开始的 `seats` 和 `weapons` 名称。载具未限制座位或武器时，可能影响其全部武器定义。

`projectiles`、`requires_vehicle`、`min_projectiles_per_shot` 等逐次发射过滤条件，不会让定义补丁变成“只在某一发触发”的临时修改。除非确实要同时修改两类定义，否则不要在一条规则里混用枪械和载具目标；不同职责应拆开。

<a name="reload"></a>
## [5] 应用与还原

`/superbaddon shell_ejection reload_external` 会应用活动补丁并失效相关主模组缓存。返回的数量表示处理了定义，不代表玩家手上武器已经重新装填或当前选中弹药状态已经纠正。应使用新取出的武器／载具测试实际选择、装填、消耗和开火。

补丁器修改内存定义，没有通用的原始定义快照。删除或关闭补丁后，仅执行 `reload_external` **不保证恢复旧弹药表**。回退时移除覆写，完整重载主模组数据并检查结果，或者从未改动的数据包和配置备份重启。

服务端修改定义不等于客户端 JSON 自动分发。多人环境应检查客户端界面、弹药选择、扣除和开火，不能只凭单人测试判断联机行为。
