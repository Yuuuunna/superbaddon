# 弹壳物品与复装配方

[English](Shell-Reloading) | [抛壳配置](抛壳配置)

弹壳是实际注册的物品，不只是粒子效果。本附属还注册了 `superbaddon:shell_reloading` 合成序列化器，用来让一格中的指定数量弹壳与普通材料共同合成。

---

## [1] 五种内置弹壳

| 物品 ID | 说明名称 |
| --- | --- |
| `superbaddon:brass_casing` | 黄铜弹壳 |
| `superbaddon:shotgun_hull` | 霰弹壳 |
| `superbaddon:heavy_casing` | 重型弹壳 |
| `superbaddon:autocannon_casing` | 机炮弹壳 |
| `superbaddon:large_shell_stub` | 大型炮弹残壳 |

实际生成哪种物品由[抛壳配置](抛壳配置)决定。更换 casing 不会自动为新弹壳创建配方，整合包的自定义弹壳需要配套的配方数据。

## [2] 一个随模组提供的计数配方

以下是随源码提供的步枪弹药配方：要求**同一格中的 48 个黄铜弹壳**，另用三格放钢锭标签材料、火药和底火，输出 48 个步枪弹药物品。

```json
{
  "type": "superbaddon:shell_reloading",
  "category": "misc",
  "group": "shell_reloading",
  "casing": {
    "ingredient": { "item": "superbaddon:brass_casing" },
    "count": 48
  },
  "ingredients": [
    { "tag": "superbwarfare:ingots/steel" },
    { "item": "minecraft:gunpowder" },
    { "item": "superbwarfare:primer" }
  ],
  "result": { "item": "superbwarfare:rifle_ammo", "count": 48 },
  "show_notification": true
}
```

配方 ID 由数据包路径决定，例如 `data/superbaddon/recipes/rifle_ammo_from_casing.json` 对应 `superbaddon:rifle_ammo_from_casing`。修改数据包配方后使用服务端 `/reload`。

<a name="casing"></a>
## [3] 计数弹壳材料

`casing` 必填，其中包含对象形式的标准 `ingredient`，例如 item 或 tag 对象，以及必填的正整数 `count`。

数量必须能够装在同一个实际物品堆中。需要 48 个弹壳时，拆成两格各 24 个不能满足计数弹壳格要求。count 超过弹壳物品的堆叠上限，在普通合成格中就不可行。

<a name="ingredients"></a>
## [4] 其他材料

`ingredients` 是必填的标准合成材料数组，至少有一个非空条目。每个条目各占一个非空格子，按普通每次合成消耗一个物品的方式处理。数组重复列出某种材料，就需要另一个占用格；仅把一格堆得更多，不能代替两个材料条目。

应避免弹壳与普通材料定义重叠，也应避免有歧义的候选集合。匹配会遍历格子并选择第一个尚未匹配的材料，并不是穷举所有材料分配的求解器。

<a name="result"></a>
## [5] 输出与元数据

`result` 必填，使用普通物品堆输出格式，包括物品 ID 和数量。group 默认空字符串，合成书 category 回退为 misc，show_notification 默认 true。

配方将自身标记为特殊配方，`isSpecial()` 为 true。因此普通配方书中未自动发现，不代表配方被禁用；该序列化器本身也不是专门的配方查看器插件。

<a name="matching"></a>
## [6] 合成格匹配与实际扣除

没有固定形状。格子数量至少为 `ingredients.size() + 1`，实际占用必须恰好为一格弹壳加所需普通材料格，不能夹带其他物品。步枪示例需要四格，因此在标签和材料正确解析时，普通背包 2×2 合成区也能容纳。

服务端在取出结果时记录匹配的自定义配方。普通合成先消耗一个弹壳，随后 ResultSlot 钩子额外消耗 `casing.count - 1` 个，从而在受支持路径中收取完整弹壳数量。

> [!IMPORTANT]
> 绕开 `ResultSlot.onTake` 的自动合成器或自定义界面必须另行验证兼容性。能显示配方不代表扣除正确：应检查额外弹壳消耗、Shift 连续合成、材料不足和输出库存限制。不能假设所有自动化模组都会调用原版结果格钩子。

<a name="index"></a>
## [7] 内置配方文件索引

当前源码在 `data/superbaddon/recipes/` 中包含以下 14 个配方文件。具体材料和数量以对应 JSON 为准，不应仅按文件名推测数值平衡。

| 类别 | 文件 |
| --- | --- |
| 枪械弹药 | `handgun_ammo_from_casing.json`、`rifle_ammo_from_casing.json`、`shotgun_ammo_from_casing.json`、`sniper_ammo_from_casing.json`、`heavy_ammo_from_casing.json` |
| 小型炮弹 | `small_shell_aa_from_casing.json`、`small_shell_ap_from_casing.json`、`small_shell_gs_from_casing.json`、`small_shell_he_from_casing.json` |
| 大型炮弹 | `large_shell_ap_from_casing.json`、`large_shell_cm_from_casing.json`、`large_shell_gs_from_casing.json`、`large_shell_he_from_casing.json`、`large_shell_wp_from_casing.json` |

另一个已核对的具体例子：大型 AP 配方使用一个 large_shell_stub、一个 `superbwarfare:ap_head` 和一个 `superbwarfare:grain`，产出一个 `superbwarfare:large_shell_ap`。
