# 命令参考

[English](Command-Reference) | [首页](首页)

以下命令都属于 `/superbaddon`，统一要求**权限等级 2**。由 OP 或服务端控制台执行；控制台中省略开头的斜杠。单人游戏同样需要足够的命令权限。

---

## 实际注册的命令树

<pre>
/superbaddon
├─ shell_ejection
│  ├─ reload_external  <a href="#external">[1]</a>
│  └─ scan             <a href="#scan">[2]</a>
│     └─ active        <a href="#scan">[2]</a>
├─ content_control
│  └─ reload           <a href="#content">[3]</a>
└─ armor_penetration
   ├─ reload           <a href="#armor">[4]</a>
   ├─ status           <a href="#armor">[4]</a>
   └─ autofill         <a href="#autofill">[5]</a>
</pre>

本次核对的源码共注册七个命令入口，没有统一的 `/superbaddon reload`，也没有独立的击退、MTS 或载具配方重载命令。

<a name="external"></a>
## [1] 重载外部抛壳规则

```text
/superbaddon shell_ejection reload_external
```

递归读取 `config/superbaddon/shell_ejection/` 下的 JSON，替换合并规则表中的外部规则部分，应用活动弹药定义补丁，并刷新内容控制状态。内存中已经加载的数据包规则仍参与合并。

用于外部抛壳、弹药和击退配置。返回信息包括外部规则数量、应用的弹药修改和内容控制目标数量。数量只能说明条目被处理，不代表某次实际发射已经命中。

它不会重载所有数据包、重建配方、重载客户端资源，也不会重读独立的 MTS／护甲穿透文件。删除弹药覆写后，仅执行此命令不保证撤销先前内存修改，详见[弹药覆写](弹药覆写)。

<a name="scan"></a>
## [2] 生成扫描候选

```text
/superbaddon shell_ejection scan
/superbaddon shell_ejection scan active
```

前者生成默认关闭的候选规则，后者生成活动候选规则。两者都会扫描注册与已加载内容、写入生成文件、重载外部规则表、应用活动弹药补丁并刷新内容控制。

> [!WARNING]
> **两者都不是只读预览。** 都会删除并重建 `generated_scan/`，并移除旧 `generated_scan.json`。即使普通 scan，也可能让依赖原有活动生成规则的行为停止。执行前先备份，并把长期维护规则移到 `custom/`。

输出包含候选规则／文件、枪械／载具类型、临时创建检查的载具实例、已加载载具武器所有者、命名空间和弹药修改数量。这些不是兼容性测试结论，具体解释与安全操作见[抛壳扫描命令](抛壳扫描命令)。

<a name="content"></a>
## [3] 重载内容控制状态

```text
/superbaddon content_control reload
```

重读 `config/superbaddon/content_control.json`，重建查询表和派生资源过滤器，不会追溯重建配方表，也不会刷新客户端资产。配方变化使用服务端 `/reload` 或重启；资源配置应重启涉及的客户端／服务端并验证。矿物生成变化应检查新地形，不是已有区块。

普通物品／方块的 recipes_only 限制和已有载具被阻止加载的风险，详见[内容控制](内容控制)。

<a name="armor"></a>
## [4] 护甲穿透重载与状态

```text
/superbaddon armor_penetration reload
/superbaddon armor_penetration status
```

reload 重读 armor_penetration.json；status 输出开关状态、部分／完整穿透配置数量和文件路径。status 主要用于读取状态，不会测量某次伤害的实际穿透率。

配置零值或关闭配置查询后，仍可能回退到弹射物原生穿透。应按[护甲穿透](护甲穿透)中的查询顺序理解，不要假设状态开关关闭了所有穿透机制。

<a name="autofill"></a>
## [5] 补充缺失的穿透候选

```text
/superbaddon armor_penetration autofill
```

扫描已加载的载具武器定义，将缺失的启发式穿透条目追加到 JSON 后重载。已经配置的 ID 会保留；它不是破坏性重置全部平衡数值，也不是精确弹道计算。

执行前备份有效文件，执行后检查新增 ID、被跳过的通用武器和警告，再验证实际伤害路径。配置格式错误时，应先修复，再使用会写入文件的命令。

## 服务端 `/reload` 是另一个命令

Minecraft 服务端 `/reload` 会重载数据包并调用本附属注册的重载监听器。修改数据包抛壳／配方或载具配方覆写后可使用它。它不属于上述七个附属命令，也不能代替客户端缓存资源配置变化时需要的实例重启。

## 命令失败检查

找不到命令根节点时，先检查服务端是否加载附属以及执行者权限。解析失败时，保留完整错误与对应文件。命令成功却无效果时，检查实例目录、实际目标 ID、活动规则字段和所需重载层级。不要把反复执行 scan active 当成通用修复方式。
