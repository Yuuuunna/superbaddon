# 配方禁用指南

[English](Recipe-Blocking-Guide) | [内容控制](内容控制)

首先区分三个标识符：**配方 ID、输出物品 ID、输出载具实体 ID**。本附属的内容和载具配方设置主要按输出匹配，不是按任意配方 ID 匹配。

---

## [1] 选择正确系统

| 目标 | 推荐方式 |
| --- | --- |
| 禁用某载具的匹配装配配方，但不阻止实体 | vehicle_recipe_override.json 中 disabled: true，或载具内容模式 recipes_only |
| 修改装配成本／分类 | [载具配方覆写](载具配方覆写) |
| 普通物品保留，只禁用配方 | 使用整合包已经验证的配方／数据包／脚本方式；当前普通 recipes_only 路径存在缺口 |
| 同时排除受支持内容和相关资源 | 完成存档安全测试后使用[内容控制](内容控制)的 block_load |
| 修改计数弹壳配方 | 按实际数据包配方路径覆写 JSON，参见[弹壳复装](弹壳复装) |

不要为了隐藏配方而裁剪资源，也不要认为空 inputs 数组能够禁用载具合成。

## [2] 只移除载具装配配方

将下面完整对象写入 config/superbaddon/vehicle_recipe_override.json：

```json
{
  "groups": {},
  "overrides": {
    "superbwarfare:ah_6": { "disabled": true }
  }
}
```

执行服务端 `/reload`。它移除既有的匹配载具装配配方，不主动限制 AH-6 实体和资源；其他配置若另有禁止，则仍会生效。

也可以使用完整的内容控制形式：

```json
{
  "items": {},
  "vehicles": { "superbwarfare:ah_6": "recipes_only" },
  "blocks": {},
  "worldgen_ores": { "superbwarfare": false }
}
```

建议选择一处长期维护的限制来源，不要在多个文件重复表达相同意图。恢复合成时必须移除所有独立限制，并重建配方表。

## [3] 普通物品／方块配方限制

枚举将 recipes_only 描述为只删除配方，但当前普通输出过滤调用 blocksItemStack，而后者检查的是 block_load。因此，在 items 或 blocks 中将普通输出设为 recipes_only，不能作为本源码快照中可靠的只删配方方式。

本文档不会用影响更大的 block_load 偷换目标来假装修复。应选择整合包已经验证的按配方 ID／输出删除机制，或适用于该序列化器的明确数据包配方覆写。脚本接口取决于实际工具版本，因此这里不编造通用命令。

在整合包修改记录中保存真实配方 ID、序列化器类型与输出。一个物品可能有多条配方，移除某个 ID 不等于封锁所有获取方式。

## [4] 输入材料过滤的边界

对于受支持的普通配方，若某个必需材料的所有明确物品候选都被禁止，配方可能被移除；仍有可用候选时则可保留。材料包含标签时，过滤器为避免在标签尚未完整绑定阶段解析，会保守保留这条材料路径。

动态／自定义配方可能不提供完整结果或材料信息。掉落、交易、命令、创造栏和脚本直接发放物品也不是普通配方。因此配方移除不是通用获取禁令。

## [5] 重载顺序与多个修改来源

配方加载后监听器先重载内容控制和载具覆写，再删除被禁配方，最后改写幸存载具配方的材料和分类。配方已经删除时，仅填写 inputs 不会让它复活。

该监听器设计上位于配方加载和预期的 KubeJS 改写阶段之后；其他重载集成仍可能改变最终结果，必须实际测试。不要把配方查看器缓存当成服务端最终配方表。

`/superbaddon content_control reload` 只刷新查询条件；真正重建配方表应使用服务端 `/reload` 或重启。

## [6] 验收与回退

检查对应合成／装配界面及实际材料消耗，再检查一个无关输出和同物品的替代配方。计数弹壳合成还应测试数量不足和连续合成，不能只看显示的输出。

记录日志中的移除 ID 和覆写数量。载具覆写匹配零个配方的警告，通常需要排查输出 ID 错误、配方已被其他来源移除、或目标根本没有装配配方。

回退时移除对应限制／覆写，从原始数据包／脚本输入重新加载。只有查询表重载，不能在不重建的情况下自动恢复已被过滤的配方表。
