# 安装

[English](Installation) | [首页](首页)

本项目是 **SuperbAddon**，模组 ID 和配置目录名均为 `superbaddon`。旧说明中的 `SuperbAH6`、`config/superbah6/` 不适用于本次核对的源码。

---

<a name="requirements"></a>
## [1] 环境与依赖

| 组件 | 当前源码要求／构建基线 |
| --- | --- |
| Minecraft | 构建目标 **1.20.1**；元数据声明范围为 `[1.20.1,1.21)` |
| 加载器 | 元数据最低要求 **Forge 47.4.0**；构建使用 47.4.0 |
| Java | **17** |
| SuperbWarfare 卓越前线 | 双端必需；元数据最低要求 **0.8.9.1** |
| GeckoLib | 双端必需；元数据最低要求 **4.4.6** |
| MTS／Immersive Vehicles | 可选；使用对应兼容功能和内容包时才需要 |

> [!IMPORTANT]
> 当前元数据要求的卓越前线最低版本是 0.8.9.1，不是 README 旧文字中的 0.8.9。声明的版本范围不等于范围内所有版本均已实测；附属使用了主模组内部接口，升级后必须验证。此构建不是 Fabric 版本。

## [2] 客户端安装

1. 创建 Minecraft 1.20.1 的 Forge 实例，使用 Forge 47.4.0 或经过实际验证的兼容版本，并指定 Java 17。
2. 将 SuperbWarfare、GeckoLib 和 SuperbAddon 的 JAR 放入该实例的 `mods/`。移走重复或过时的同 ID 模组文件。
3. 需要 MTS 联动时，再安装 MTS 及所选载具、弹药需要的内容包。
4. 启动游戏并进入一次测试世界，让相关配置系统完成初始化。
5. 在该实例的 `config/superbaddon/` 下编辑配置，随后按[快速开始](快速开始)验证。

## [3] 独立服务端安装

服务端的 `mods/` 也需要对应的玩法模组和必需依赖，启动时使用 Java 17。服务端规则位于**服务端工作目录**的 `config/superbaddon/`，不是玩家电脑上的同名目录。

服务端配置决定服务端玩法；客户端资源过滤和操控还会读取客户端本地配置。本附属没有通用的 JSON 文件自动下发协议。应随客户端整合包分发一致的内容／资源规则，同时将玩家自己的 MTS 操控偏好与服务端配置分开管理，详见[兼容性](兼容性)。

[管理命令](命令参考)需要权限等级 2，可由 OP 或服务端控制台执行。控制台中省略开头的 `/`。

## [4] 安装检查

检查模组列表中是否存在 `superbaddon`、依赖检查是否通过、测试世界能否加载。查看 `logs/latest.log`，以及环境生成的 `logs/debug.log` 中的启动和配置错误。在测试世界发射受支持武器，确认弹壳行为；再以管理员身份执行 `/superbaddon armor_penetration status`，确认命令已注册。

未安装可选的 MTS 不应成为必须移除本附属的理由；缺失必需依赖则属于安装问题，不能靠修改抛壳规则解决。

## [5] 更新与卸载

变更版本前备份存档和配置。手工规则不要长期放在 `generated_scan/`。升级时先查看[数据格式版本](数据格式版本)和[已知问题](已知问题)，不要为了重新生成默认值而直接删除已经定制的配置。

本附属注册了实际物品，不能把“内容控制”当成卸载或注册表迁移工具。在重要存档中移除模组前，必须先完成备份和迁移测试。
