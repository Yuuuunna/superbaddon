# 兼容性

[English](Compatibility) | [安装](安装)

兼容性需要区分三层：依赖声明允许加载、附属实现了受保护的集成路径、某个实际组合通过了运行测试。本页记录前两层，不编造第三层结论。

---

## [1] 必需环境

当前源码基于 Minecraft 1.20.1、Forge 47.4.0、SuperbWarfare 0.8.9.1 和 GeckoLib 4.4.6，使用 Java 17。运行时元数据声明相关库为双端依赖，最低版本和范围详见[安装](安装)。

即使后续依赖版本仍满足宽泛范围，Mixin 目标、原始武器数据字段和反射缓存内部结构也可能改变。应保持双端玩法构建一致，并在测试实例验证升级。此源码不是 Fabric 构建。

## [2] 可选集成表

| 集成 | 已实现边界 | 仍需验证 |
| --- | --- | --- |
| MTS／Immersive Vehicles | 受保护的燃料桥接、弹药数量、客户端操控与视角路径 | 实际 MTS 构建、内容包、库存实现、视角模组与联机行为 |
| Epic Core API，ID 为 eca | 可选生命值设置入口；缺失或失败时返回原生回退路径，错误仅记录一次 | 实际 ECA 组合中的防御机制和事件行为 |
| KubeJS 或其他配方重写 | 加载后监听器设计上在预期脚本阶段之后处理最终配方表 | 全部配方集成与缓存参与后的真实顺序 |
| 数据包抛壳规则 | 与外部文件共用 format 5 解析和合并排序 | 冲突 ID／优先级及主模组定义加载顺序 |
| 自动合成 | 计数弹壳配方与原版 ResultSlot 消耗钩子 | 绕开该钩子的机器或自定义界面 |

MTS 不是附属基础加载的必需条件。ECA 门面先检查 eca 模组存在，再引用有类型依赖的实现，并捕获链接／运行时异常。这些保护减少可选依赖耦合，不是对无关 API 的通用兼容。

## [3] 服务端玩法与客户端本地数据

外部配置属于各自实例。这里没有把服务端所有 JSON 自动写入玩家 config 目录的通用机制。服务端执行其负责的掉落、伤害和配方管理；客户端仍需要对应安装内容，以及相关路径会读取的本地资源／操控设置。

应随客户端整合包分发约定的内容／资源配置，但不要为了同步服务端燃料设置而无差别覆盖玩家操控偏好。验证加入和重新连接，不能只测试单人世界。

## [4] 伤害与物理集成

护甲穿透通过专用生命伤害路径处理受支持的卓越前线伤害类型及生物实体，保留明确的无敌、游戏模式和队伍检查，但不保证复现其他伤害模组期待的全部回调或防御机制。

击退配置通过受支持的弹射物和自定义爆炸钩子传递，不自动拦截其他模组直接改速度、近战击退或自定义伤害路径。视角倾斜和 MTS 输入同样不替换载具物理。详见[护甲穿透](护甲穿透)和[击退配置](击退配置)。

## [5] 内容与配方集成

内容过滤在同一命名空间内遵循已知资源布局，共享模型、自定义布局、标签材料和动态配方结果都可能改变预期效果。block_load 不是通用注册表卸载操作，普通 recipes_only 输出过滤也存在已知缺口。

载具覆写作用于主模组 VehicleAssemblingRecipe 类型并保留输出。其他拥有相似界面的自定义配方类型不会自动受支持。详见[资源裁剪指南](资源裁剪指南)、[配方禁用指南](配方禁用指南)和[已知问题](已知问题)。

## [6] 升级验收

升级依赖前保留旧 JAR、配置和存档组合。先检查启动阶段 Mixin／链接错误，再逐项执行整合包实际使用的集成功能示例，同时比对双端日志。按[推荐工作流](推荐工作流)记录确切版本与结果。

本次文档补全没有执行游戏运行、大型整合包或独立服务端验收测试。决定是否部署到重要存档时，应保留这个区别。
