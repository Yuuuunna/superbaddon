# 配置总览

[English](Configuration-Overview) | [首页](首页)

SuperbAddon 使用多个独立的配置系统，而不是把所有功能塞进一个文件。修改前先确定目标行为由哪个系统负责。

> [!IMPORTANT]
> 抛壳规则不负责启用或禁用注册内容；载具配方覆写不负责改载具实体；击退与护甲穿透是两套独立系统。当前源码没有单独的 `common.json` 或 `knockback.json` 加载器。

---

## 完整配置布局

点击行末编号跳转到对应说明。以下路径均相对于正在运行的游戏实例或服务端工作目录。

<pre>
config/
└─ superbaddon/
   ├─ content_control.json                  <a href="#content">[1]</a>
   ├─ vehicle_recipe_override.json          <a href="#recipes">[2]</a>
   ├─ mts_compat.json                       <a href="#mts">[3]</a>
   ├─ armor_penetration.json                <a href="#armor">[4]</a>
   └─ shell_ejection/                       <a href="#shell">[5]</a>
      ├─ custom/
      │  └─ my_rules.json
      └─ generated_scan/
         └─ &lt;namespace&gt;/
            ├─ items/
            └─ vehicles/

&lt;world&gt;/datapacks/&lt;pack&gt;/data/&lt;namespace&gt;/
├─ shell_ejection/                          <a href="#datapacks">[6]</a>
└─ recipes/                                <a href="#datapacks">[6]</a>
</pre>

配置文件在对应加载器首次需要时创建；主菜单阶段未出现某个可选配置，不一定是错误。`custom/` 只是推荐的整理方式，并非优先级更高的特殊目录。详见[配置目录结构](配置目录结构)。

<a name="content"></a>
## [1] `content_control.json`

用于受支持的物品、载具、方块和矿物生成控制。省略说明文字后的默认结构为：

```json
{
  "items": {},
  "vehicles": {},
  "blocks": {},
  "worldgen_ores": { "superbwarfare": false }
}
```

目标使用注册 ID，模式为 `keep`、`recipes_only` 或 `block_load`。`worldgen_ores` 中 **true 表示禁用** 对应受支持的矿物生成，不会删除已经生成的矿石。

当前配方过滤实现对载具装配输出处理了 `recipes_only`，但普通物品／方块输出存在已知缺口。不要不加说明地换成影响更大的 `block_load`。详见[内容控制](内容控制)、[配方禁用指南](配方禁用指南)和[已知问题](已知问题)。

<a name="recipes"></a>
## [2] `vehicle_recipe_override.json`

按输出的载具实体 ID 修改既有 `superbwarfare:vehicle_assembling` 配方。支持 `disabled`、`category`、`inputs`，并提供 `groups` 与单体 `overrides`。

```json
{
  "groups": {},
  "overrides": {
    "superbwarfare:ah_6": {
      "inputs": ["8 minecraft:iron_block"]
    }
  }
}
```

以上是成本覆写示例，不是默认配方。单体覆写会整份替换所属组规则，不会继承组内省略的字段；输出的载具本身不会被更换。详见[载具配方覆写](载具配方覆写)。

<a name="mts"></a>
## [3] `mts_compat.json`

用于可选的燃料转换、油桶、油泵设置，以及持久化的客户端操控桥接偏好。`default_energy_per_bucket` 默认是 `0`，因此未列出的液体默认不能作为燃料。

虽然共用文件，服务端燃料行为与客户端操控偏好仍是不同职责。倾斜视角开关只在当前会话保存，不是额外的 JSON 字段。完整默认值与操作见[MTS兼容](MTS兼容)。

<a name="armor"></a>
## [4] `armor_penetration.json`

包含 `enabled`、`armor_penetration_by_weapon`、`full_armor_bypass_weapons` 和 `explosion` 衰减参数，不应放进抛壳规则文件。

修改后使用 `/superbaddon armor_penetration reload`；`status` 用来检查加载数量；`autofill` 只补充缺失的启发式默认值，并不保证数值平衡。详见[护甲穿透](护甲穿透)。

<a name="shell"></a>
## [5] `shell_ejection/**/*.json`

该目录内所有普通 JSON 文件都会递归扫描。必需的顶层包装为：

```json
{
  "format": 5,
  "rules": []
}
```

每条规则可以包含 `enabled`、`priority`、对象类型的 `target`、`ammo_override`、`ejection` 和 `knockback`。这些部分可以独立使用：只改击退时不必生成弹壳，也不必更换弹药。

详见[抛壳配置](抛壳配置)、[弹药覆写](弹药覆写)、[击退配置](击退配置)。查找目标时使用[抛壳扫描命令](抛壳扫描命令)。

> [!WARNING]
> 扫描会删除并重建 `generated_scan/`，同时删除旧 `generated_scan.json`。长期维护的规则放在 `custom/`，备份放在扫描目录之外。根对象中的 `enabled_by_default`、`owner`、嵌入式 `content_control` 等元数据，不能代替规则字段或独立的 `content_control.json`。

<a name="datapacks"></a>
## [6] 数据包

数据包中的抛壳规则使用同一个 format 5 解析器。内置规则与外部规则按数值优先级和规则 ID 合并，外部文件不会天然优先。包括[弹壳复装](弹壳复装)在内的数据包配方应位于 `recipes/`，不是外部抛壳目录。

## 在正确层级应用修改

| 修改内容 | 对应操作 |
| --- | --- |
| 外部抛壳／击退规则 | `/superbaddon shell_ejection reload_external` |
| 数据包抛壳规则或合成配方 | 服务端 `/reload`，并检查重载日志 |
| 载具配方覆写、内容控制涉及的配方表 | 服务端 `/reload` 或重启 |
| 护甲穿透 JSON | `/superbaddon armor_penetration reload` |
| 仅刷新内容控制查询状态 | `/superbaddon content_control reload`；它本身不会重建配方和资源 |
| 客户端资源裁剪、矿物生成配置 | 重启涉及的客户端／服务端再验证；不会重新生成旧区块 |
| MTS 文件修改 | 重启对应实例；当前没有专用 MTS 重载命令 |

弹药覆写会修改内存定义，撤销时应完整重载数据或重启，并确认还原效果。不能假设删掉文件就能撤销所有内存修改。详见[通用配置](通用配置)与[推荐工作流](推荐工作流)。
