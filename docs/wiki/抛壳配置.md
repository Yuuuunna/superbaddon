# 抛壳 JSON 格式

[English](Shell-Ejection) | [配置总览](配置总览)

本页说明当前 **format 5** 解析器和服务端弹壳行为。[弹药覆写](弹药覆写)与[击退配置](击退配置)使用同一规则容器，但负责不同功能。

> [!IMPORTANT]
> 提供 `target` 时必须使用对象。旧示例中的字符串目标、将根对象 `enabled_by_default` 当作行为开关、将嵌入式 `content_control` 当作活动内容配置，都不符合当前实现。旧文原样保存在页脚链接的源码归档中。

---

## 完整可用结构

保存为 `config/superbaddon/shell_ejection/custom/ak47_casing.json`。该示例不修改弹药定义，使用本附属注册的黄铜弹壳。

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": {
        "guns": ["superbwarfare:ak_47"]
      },
      "ejection": {
        "default": {
          "mode": "drop",
          "casing": "superbaddon:brass_casing",
          "count": 1,
          "chance": 1.0,
          "pickup_delay": 20,
          "fallback_to_drop": false,
          "ports": [
            {
              "id": "right_port",
              "offset": [0.2, -0.05, -0.15],
              "velocity": [0.08, 0.08, -0.02],
              "random_velocity": 0.035
            }
          ]
        }
      }
    }
  ]
}
```

## [1] 文件包装与规则控制

根对象必须包含数值 `format: 5` 和 `rules` 数组。直接提供单条规则、根数组、缺失 format 或其他格式编号，都会被拒绝。数组中非对象条目会被跳过；规则对象内 `enabled` 省略时默认 true，维护文件建议显式填写。

`priority` 是整数，默认 `0`。规则先按优先级降序，再按完整规则 ID 升序排序。外部 ID 来自相对文件名与规则数组下标，因此重命名文件或调整同优先级规则顺序可能影响结果。外部文件不会天然高于数据包。

根对象中的 `generated_by`、`generated_at`、`owner_type`、`owner`、`note`、`enabled_by_default`、`content_control` 对当前解析器只是元数据。内容控制应写到[独立文件](内容控制)。

<a name="target"></a>
## [2] `target`

| 字段 | 支持形式 | 匹配含义 |
| --- | --- | --- |
| `guns` | 字符串或字符串数组 | 发射上下文中的枪械数据／物品 ID |
| `projectiles` | 字符串或字符串数组 | 发射上下文中的弹射物 ID |
| `vehicles` | 字符串或字符串数组 | 载具实体 ID |
| `weapons` | 字符串或字符串数组 | 载具武器名，或 `载具ID/武器名` |
| `seats` | 整数或整数数组 | 从 0 开始的载具座位下标 |
| `requires_vehicle` | 布尔值，默认 false | 要求存在载具上下文 |
| `min_projectiles_per_shot` | 整数，默认 0 | 本次发射报告的最小弹射物数量 |

同一集合内命中任意一项即可，**不同非空字段之间是同时满足的 AND 条件**。空目标或省略目标会扩大匹配范围，不代表关闭规则，不要误投放全局测试规则。

载具武器名请通过[扫描](抛壳扫描命令)查看实际值。武器名不一定是物品 ID，也不是模型骨骼名；枪械和载具 ID 不能混用。弹药补丁修改的是定义，不会把所有发射条件都当作逐次发射限制，详见[弹药覆写](弹药覆写)。

<a name="selection"></a>
## [3] `ejection.by_ammo` 与 `ejection.default`

`by_ammo` 是“弹药规格 → 抛壳配置”的对象。匹配使用规范化后的已选弹药 ID **或**规格字符串，不是严格 NBT 相等检查；提取后 ID 相同的弹药变体可能互相重叠。

单条规则内，先按声明顺序寻找第一个匹配的 `by_ammo`，再尝试 `default`。此外还有一个较窄的历史回退：只有一个弹药抛壳条目，且活动弹药覆写中只有一个允许项并命中本次发射时，可使用该唯一条目。应主动对齐弹药键，不要依赖这条回退猜测目标。

以下完整示例只为指定弹药生成弹壳，其他弹药不生成：

```json
{
  "format": 5,
  "rules": [
    {
      "enabled": true,
      "priority": 1000,
      "target": { "guns": ["superbwarfare:ak_47"] },
      "ejection": {
        "by_ammo": {
          "superbwarfare:rifle_ammo": {
            "mode": "drop",
            "casing": "superbaddon:brass_casing"
          }
        },
        "default": { "mode": "none" }
      }
    }
  ]
}
```

实际填写时应使用安装环境中选中的弹药 ID／规格；使用其他虚拟弹药或标签规格的武器，不一定命中示例中的键。`by_ammo` 不会自动允许枪械装填该弹药；只改抛壳的规则也不需要填写 `ammo_override.allowed`。

<a name="mode"></a>
## [4] 处理模式与存储回退

| 推荐模式名 | 行为 |
| --- | --- |
| `drop` | 对每个通过概率检查的抛壳点尝试生成掉落物 |
| `store` | 只使用第一个点，通过 Forge 物品处理能力向上下文指定的存储目标插入弹壳 |
| `none` | 本条已选中的抛壳规则不生成、也不存储弹壳 |

默认是 `drop`。保留的 store 别名包括 `stored`、`collect`、`container`；none 别名包括 `ignore`、`discard_no_visual`、`disabled`。未知取值回退为 drop，维护文件建议只用表中的推荐名称。

`fallback_to_drop` 默认 **false**，仅处理 `store` 模式中未能插入的剩余物品。设为 true 时，库存不足或没有存储能力可以将余量改成掉落；设为 false 时余量不会生成。它**不是**错误坐标、无效弹壳或 JSON 格式错误的通用回退。

要在其他低优先级规则存在时禁止抛壳，应保留一条足够高优先级的活动匹配规则并选用 `mode: "none"`。直接关闭这条规则会让其他规则重新有机会匹配。

<a name="casing"></a>
## [5] 弹壳字段与默认值

| 字段 | 默认值 | 含义／校验 |
| --- | --- | --- |
| `casing` | `superbaddon:brass_casing` | 注册的物品 ID；缺失、空气或无效物品不会产生有效物品堆 |
| `count` | `1` | 每个点的物品堆数量，最小为 1 |
| `chance` | `1.0` | 每点概率，限制在 0–1 |
| `pickup_delay` | `20` | 不可拾取时间，单位 tick，非负；正常 tick 速率下 20 tick 约一秒 |
| `offset` | `[0.2,-0.05,-0.15]` | 发射坐标基准中的位置偏移 |
| `velocity` | `[0.08,0.08,-0.02]` | 同一基准中的初速度 |
| `random_velocity` | `0.035` | 非负随机扰动幅度 |

`count: 0` 不会关闭弹壳，而会变成 1。drop 模式的 count 是一个掉落物品堆里的数量，并非要求生成 count 个独立实体；更多抛壳口和更多开火事件仍会增加掉落实体数量。弹壳物品与合成用途见[弹壳复装](弹壳复装)。

运行时代码在进入掉落循环前先检查第一个点的弹壳物品；第一个弹壳无效时，后续本来有效的点也可能无法生成。因此应检查所有 casing ID。

<a name="ports"></a>
## [6] 抛壳口与坐标基准

`ports` 是对象数组。每个点可以覆写 `id`、`casing`、`count`、`chance`、`pickup_delay`、`offset`、`velocity`、`random_velocity`；省略的字段继承该抛壳条目的回退值。`id` 只是标签，不会绑定模型骨骼。

未提供有效 `ports` 数组时兼容旧名称 `points`。空数组或只包含无效项的数组会回退为一个点，而不是关闭抛壳。向量应写成三个数值组成的数组，不要写成 `{x,y,z}` 对象。

坐标基准由发射前向、世界向上和水平侧向 `(-forward.z, 0, forward.x)` 组成。X 为侧向分量，Y 为世界向上，Z 沿发射方向；**它不是包含载具滚转的完整骨骼局部变换**。存在发射位置时以发射位置为原点。初速度还会加上射手移动速度的四分之一和随机扰动。

先调一个点，在不同朝向和移动载具上验证，再增加更多抛壳口。store 模式不会处理第二个存储点。

<a name="testing"></a>
## [7] 规则选择、重载与排查

抛壳选择第一条“目标匹配且能选出抛壳配置”的规则。目标匹配但没有适用抛壳条目时，较低规则仍可能提供抛壳。击退独立选择；弹药定义则使用自己的合并方式。

外部文件使用 `/superbaddon shell_ejection reload_external`；数据包规则使用服务端 `/reload`。查看日志中的文件解析错误、加载数量和竞争规则。一条格式错误的规则可能导致整个文件解析失败，不要假设同文件其他规则一定保留。

验证时使用实际配置的枪、载具武器、座位和弹药变体。无弹壳时依次检查 enabled、目标交集、优先级、已选弹药、mode、casing ID、存储空间，以及内容控制是否禁止弹壳物品。详见[故障排查](故障排查)。
