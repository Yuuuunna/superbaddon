# 设计说明

[English](Design-Notes) | [数据格式版本](数据格式版本)

本页为维护者提供当前实现地图，明确每个决策由哪个组件负责，避免新增文档或修复时把独立配置系统错误地混为一体。

---

## [1] 配置职责

| 系统 | 权威输入 | 主要实现 |
| --- | --- | --- |
| 内容限制 | content_control.json | ContentControlConfig、ContentControlManager、ResourcePaths 与运行时／资源钩子 |
| 载具装配 | vehicle_recipe_override.json 和原始配方 | VehicleRecipeOverrideConfig／Manager、加载后配方重写 |
| 发射规则 | 数据包和外部 format 5 文档 | ShellRuleParser、ShellRuleSet 与各运行时消费者 |
| 穿透 | armor_penetration.json 加原生弹射物回退 | ArmorPenetrationConfig／Rules、CopiedHurtCalculator |
| MTS 燃料／输入偏好 | mts_compat.json 加客户端会话状态 | MtsCompatConfig、燃料事件／连接与受保护操控实现 |
| 计数弹壳合成 | 数据包配方 | ShellReloadingRecipe、ResultSlotMixin |

共用配置容器不代表共用一种合并方式。抛壳、弹药补丁和击退复用目标／数据结构，但拥有不同的生命周期和选择语义。

## [2] 发射规则数据流

```text
数据包抛壳 JSON ─┐
                ├─ format 5 解析 ─ 排序后的合并规则表
外部抛壳 JSON ───┘                         │
                   ┌──────────────────────┼──────────────────┐
                   │                      │                  │
               弹药定义补丁           逐次发射抛壳       逐次发射击退
               合并与缓存失效         选择抛壳配置       选择整份配置
                   │                      │                  │
               枪械／载具定义         服务端掉落／存储   弹射物／爆炸钩子
```

数据包重载替换数据包规则并刷新外部规则；外部重载只替换该来源的规则，然后应用活动弹药补丁。数值优先级降序、规则 ID 升序形成确定顺序，但弹药补丁是合并，不采用抛壳的首条匹配方式。

弹药修改会变更定义并失效缓存，当前没有用于撤销被移除补丁的通用原始定义快照。文档必须明确这种生命周期，不能把规则表替换描述为事务式撤销。

## [3] 内容与配方层

内容配置生成规范化目标模式和已知资源路径条件。资源钩子过滤访问／列举，部分运行时钩子过滤创造栏物品堆、掉落物、容器或载具加入。这不是删除注册表，也不会覆盖物品／方块的一切用途。

配方监听器在加载之后重读相关配置，改写最终表。删除先于载具重建；重建保留 ID 与输出，仅替换选中的材料／分类字段。

正确性检查必须跟踪调用点，而不能只看枚举名：普通 recipes_only 缺口正是因为普通输出分支调用了被禁物品堆查询，而非禁配方查询。早期材料检查则保守保留带标签路径。

## [4] 伤害与冲量层

护甲穿透解析受支持的枪械／弹射物 ID，拆分可防御和穿透伤害，并使用专用生命伤害路径。爆炸上下文传递来源穿透和距离衰减，包括受支持的延迟冲击波路径。配置零值不一定停止原生弹射物回退。

击退则在发射附近捕获配置，通过受支持的弹射物／爆炸钩子传递。直击和爆炸通道独立，弹药专用覆写按整个非纯继承通道替换。这不是给其他模组通用使用的物理服务。

两套机制可以并存，但不能在文档中合称一个“伤害强度”参数。护甲、吸收、冲量和爆炸距离应分别验证。

## [5] 可选集成与权威边界

MTS 燃料在服务端操作载具能量和液体数量；客户端操控驱动 MTS 自己的变量／数据包，不替换物理。视角倾斜属于会话本地状态，与保存的输入偏好独立。弹药数量适配 bulletQty，不将一个物品直接视为一发。

有类型依赖的可选桥接在使用前受保护。ECA 门面在缺失或链接／运行时失败时返回 false，让调用者选择原生回退。这些门面都不是通用配置文件同步机制。

## [6] 维护变更检查

新增字段时，同步检查解析器、默认值、范围／单位、合并规则、消费者、重载行为和双语页面。新增规则效果时，先决定它是定义期修改还是逐次发射决策，再决定是否复用目标字段。

修复限制时，应增加相应回归检查，再修改已知问题说明；不能因为枚举或注释表达了预期，就删除实际限制警告。保留主模组接口边界，并测试真实编译／部署使用的依赖版本。

文档需要维护对应双语页面及可达侧栏，使用完整有效 JSON 和独立编号说明。发布前执行 `python3 docs/validate_wiki.py`。该校验器检查文档结构，不检查游戏正确性，也不保证任意远程地址可访问。

同步工作流更新受源码管理的 Wiki 页面，不删除其他实时页面。历史内容应归档在 docs/wiki/ 之外，既保存在仓库，又不把过时示例重新发布成当前说明。
